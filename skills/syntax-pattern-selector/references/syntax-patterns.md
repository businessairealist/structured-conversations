# Syntax Patterns

## Purpose

Use this reference as a lightweight catalog of framing formats for product and delivery conversations.

## Pattern Catalog

### Requirement statement

Use when the team needs a direct statement of what the system or product should do.

Good for:

- clear delivery expectations
- stakeholder signoff
- direct scope communication

### Hypothesis statement

Use when the team is testing an assumption or expected outcome.

Good for:

- experiments
- discovery work
- uncertain opportunity spaces

### Job story

Use when context, motivation, and expected outcome matter more than persona labels.

Good for:

- behavior framing
- user context
- outcome-driven conversation

### Traditional user story

Use when the team needs a familiar delivery-ready format and the actor-action-benefit shape is enough.

Good for:

- backlog drafting
- agile delivery teams
- lightweight story framing

### Feature definition

Use when the discussion centers on capability boundaries, key rules, or scope framing for a feature.

Good for:

- feature clarification
- product-definition work
- aligning teams around capability intent

### Event rule

Use when the key issue is what must happen when a triggering condition occurs.

Good for:

- rules engines
- notifications
- transactional or state-change behavior

### Constraint story

Use when the core concern is a limitation, policy, quality attribute, or guardrail.

Good for:

- compliance
- non-functional requirements
- operational boundaries

## Quick Routing Guide

- If the team is learning, prefer a hypothesis statement.
- If the team is clarifying user context, prefer a job story.
- If the team is preparing backlog delivery, prefer a user story or requirement statement.
- If the team is defining system behavior around triggers, prefer an event rule.
- If the team is setting boundaries, prefer a constraint story.
- If the team is clarifying capability scope, prefer a feature definition.

## Good End State

The chosen pattern is strong when the statement becomes easier to review, easier to challenge, and easier to hand off to the next skill or teammate.
