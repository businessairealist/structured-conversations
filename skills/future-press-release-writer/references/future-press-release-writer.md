# Future Press Release Writer Reference

## Purpose

Use this reference when drafting the final future press release after a
structure has been chosen.

The press release should read as though launch has already happened and the
customer benefit is now real.

## Writing Rules

- write from the future state, not as a speculative plan
- keep the target customer and problem explicit
- make the promised benefit concrete
- use quotes and experience details only when they reinforce the product story
- preserve uncertainty in assumptions and open questions instead of burying it

## Upstream Inputs

Strong upstream sources include:

- a structure-selection artifact
- an elevator pitch
- empathy, journey, or impact artifacts
- source notes under `inputs/notes/`

## Render Guidance

The writer output is not the comparison canvas. It is the completed press
release in the selected structure, rendered as a readable HTML document with
clear section boundaries.
