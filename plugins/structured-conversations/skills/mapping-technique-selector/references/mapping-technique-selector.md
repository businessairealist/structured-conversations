# Mapping Technique Selector Reference

## Purpose

Use this reference to choose the best mapping technique for an alignment or discovery problem and to route the team toward the right downstream artifact.

This reference focuses on selection and facilitation guidance, not project-runtime mechanics.

## Core Outcome

A good selection does all of the following:

- identifies the real alignment problem
- recommends one best-fit mapping technique
- explains why that technique fits
- provides a lightweight facilitation plan
- points to the downstream skill that should create the artifact

## Default Selection Flow

Use this sequence unless the request is already tightly constrained:

1. Capture the source problem.
2. Identify the decision, confusion, or alignment gap.
3. Determine what kind of structure is missing.
4. Compare the relevant mapping techniques.
5. Select the best-fit technique.
6. Draft a lightweight facilitation plan.
7. Record expected outputs, assumptions, and open questions.

## Selection Heuristics

- Choose empathy-oriented maps when the problem is understanding people.
- Choose flow-oriented maps when the problem is stages, steps, or handoffs.
- Choose tree-oriented maps when the problem is outcomes, opportunities, or branching options.
- Choose rule/example maps when the problem is requirement clarity.
- Choose story-structure maps when the problem is slicing delivery or organizing backlog content.
- Route to a simpler foundation skill first when the issue is wording rather than mapping.

## Output Template

Use this shape in the structured markdown output.content` and mirror it in the human-readable summary:

- `source_problem`
- `desired_outcome`
- `available_evidence`
- `candidate_techniques`
- `selected_technique`
- `selection_rationale`
- `facilitation_plan`
- `expected_outputs`
- `recommended_downstream_skill`
- `assumptions`
- `open_questions`

## Failure Modes

Avoid these patterns:

- recommending several maps without a clear primary choice
- selecting a map because it is popular rather than structurally appropriate
- giving a workshop plan with no concrete output
- ignoring the evidence type when it changes what map is useful
