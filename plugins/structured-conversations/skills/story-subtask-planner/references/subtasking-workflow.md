# Subtasking Workflow

Use the same four-stage flow across templates, workshops, and delivery planning artifacts.

## Canonical Flow

1. current code review
2. code modification discussion and ideas
3. sequence diagram or interaction flow
4. implementation subtasks

## Why This Flow Works

- review keeps the current state and risks visible
- discussion narrows to the smallest safe implementation path
- sequence thinking exposes hidden dependencies and side effects
- subtasks become more actionable because they inherit real technical context
